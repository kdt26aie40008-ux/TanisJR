### 実機で分かったこと
- Ollama 0.40 は **LoRA アダプター単体の読み込み**にも、**GGUF の登録時量子化**にも対応していない。統合済みモデルを safetensors のまま `ollama create -q q4_K_M` で取り込む方式にした。
- 学習率 2e-4・3エポックでは少量データで出力が崩れた（「相棒、相棒、相棒」）。既定を 1e-4・2エポックに下げた。
- 30件の人工データでは、1.7B モデルの返答は話し方の一部が変わる程度で、qwen3:8b より明らかに品質が低い。実用には良質なデータを増やすか 8B での学習が必要。

### 追加: PC・ユーザーごとのデータ保存（2026-11-04）
- 保存先をプロジェクト内 `data/` から `%LOCALAPPDATA%\PersonalTwinAI\data` に変更。アカウントの仕組みは作らない。
- 新しい PC・新しい Windows ユーザーは空の状態（初回設定）から始まる。旧 `data/` はこのユーザーのものだけ自動で移動（実機: このPCのデータを移動し、初回設定済み・暗号化データとも読めることを確認）。
- ロック画面に「このPCで新しく始める」（データは退避して残す）を追加。同意文の保存場所の説明を更新し、同意文のバージョンを上げた。

### 追加: AivisSpeech エンジンの自動起動
- AivisSpeech のアプリ画面を開かなくても、エンジン（`AivisSpeech-Engine\run.exe --host 127.0.0.1 --port 10101`）だけを画面なしで起動する（設定でオン・オフ）。
- 実機: アプリ・エンジンとも停止した状態からサーバー起動 → 約18秒でエンジンが応答し、読み上げ成功。

### 追加: 標準アバターの同梱（2026-11-04）
- VRoid Studio を入れられない人向けに、男性・女性の VRM（`assets/avatars/`）をリポジトリーに同梱。「3Dアバター」画面で「使用する」を押すだけで使える（変更・削除は不可、DB には登録しない）。
- 女性は pixiv の AvatarSample を元にしたモデル。サンプルの利用条件で、改変モデルの無料配布は可・CC0 設定は禁止・**サンプルのデータを使ったキャラクター作成機能の開発は禁止**。このため女性モデルをアバター作成（パーツ組み替え）機能の素材にしないこと。
- 書き出し時の VRM 利用条件が「作者のみ・再配布不可」だったため、作者の指示で meta のみ「誰でも・法人商用可・クレジット不要・再配布可・改変可（CC0 ではない）」に書き換えた（見た目のデータは変更なし）。
- 実機: 2体とも表示・表情・口パクを確認。CharacterStudio の素材ライセンスは M3-org の回答待ち（ユーザーが問い合わせを投稿）。

### Phase 3
- 実マイク入力は未確認（Chrome/Edge で http://127.0.0.1:8765 を開き、マイクを許可して確認する）。

- バックアップにアバターファイル（VRM）は含まれない。
- 音声会話は「押して話す」方式（常時聞き取りや話し終わりの自動検出は未実装）。

### Phase 2 まで

- ChromaDB のベクトルは平文（本文は保存しない）。DPAPI は同じ Windows ユーザーからは保護できない。
- 記憶抽出の分類は LLM 依存。安全策としてキーワード（住所・勤務先・健康・家族など）でも承認待ちにするが、漏れの可能性はある。
- 重複判定の距離 0.15 は実機データで十分に調整していない。
- 応答が中断・エラーになったターンは保存しない（画面には部分的な応答が残る）。
- 承認待ち件数のバッジは画面切替時に更新（抽出は応答後のバックグラウンド処理のため、直後には反映されない）。
- 学習データ（記憶種別5）は Phase 5 で実装。
- 会話を保存せずにリロードすると会話は消える（仕様）。
- モデル保存先の表示はバックエンドプロセスの `OLLAMA_MODELS` から推定。
- `D:` ドライブの所有者情報の関係で git に `safe.directory` 設定が必要。
